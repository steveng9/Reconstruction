## Description

This artifact is the experiment framework behind:

> Steven Golob, Sikha Pentyala, Martine De Cock.
> *SoK: Reconstruction Attacks on Synthetic Tabular Data (Insights from Winning the NIST CRC).*
> Proceedings on Privacy Enhancing Technologies (PoPETs), 2027.

The paper studies **reconstruction attacks** (attribute inference) on
de-identified and synthetic tabular data: given a synthetic release and a target
record's quasi-identifiers (QIs), an attack tries to recover that record's hidden
attribute values.

The repository contains:

- every attack in the paper's taxonomy, including the six it introduces
  (CoBP-RA, CondMST, CondDDPM, CondRePaint, ARFFormer, MultiHeadMLP), and the
  chaining and ensembling wrappers;
- the synthetic-data generators: the nine methods evaluated, plus four more DP
  mechanisms used for the privacy-budget (ε) sweep;
- the scoring code for rarity-weighted reconstruction advantage ($R_{adv}$), the
  metric NIST used in its Collaborative Research Cycle;
- the driver scripts for every experiment;
- `experiment_scripts/results.db`, a SQLite database of the **50,826** scored
  attack runs behind the paper, and `reproduce.py`, which rebuilds the paper's
  tables and figures from it.

The quickest way in:

```bash
git clone --recurse-submodules https://github.com/steveng9/Reconstruction.git
cd Reconstruction
docker build -f docker/Dockerfile --build-arg UID=$(id -u) --build-arg GID=$(id -g) -t recon-artifact:latest .
docker run --rm -it -v "${PWD}":/workspace -w /workspace recon-artifact:latest bash
```

Then, inside the container:

| Command | What it does | Time |
|---|---|---|
| `./test.sh` | checks the installation end to end | ~2 min |
| `python reproduce.py` | rebuilds the paper's tables and figures from the shipped results | ~1 min |
| `python master_experiment_script.py --n_runs 1` | runs one attack on the bundled example dataset | ~1 min |

`README.md` documents the framework itself (configuration, attacks, generators,
adding your own). `DATABASE.md` documents `results.db` for anyone who wants the
results without the code.

### Security/Privacy Issues and Ethical Concerns

Running the artifact poses no risk to your machine. It trains ordinary ML models
and solves linear programs on tabular data; it disables no security mechanism
and needs no elevated privileges. Its only network access at run time is
`fetch_dataset.py` downloading two public datasets for Experiments 3 and 4
(Weights & Biases logging is optional and off by default).

The repository implements privacy attacks against synthetic-data releases. It is
published so that defenders and generator authors can measure the exposure of
their own releases. The attacks run on datasets that are already public or
released for research; they do not target a live service.

No personal data is redistributed. `data/dummy/` is machine-generated by
`data/dummy/make_dummy_data.py` and describes no real person. Real datasets are
obtained from their own sources (see *Software Requirements*). `results.db` holds
aggregate scores only: no records and no reconstructed values. The paper involved
no human subjects.

## Basic Requirements

### Hardware Requirements

A laptop with 4 CPU cores and 8 GB of RAM runs everything in this document. No
GPU is needed.

The paper's full sweeps were run on one workstation: an AMD Ryzen Threadripper
PRO 5965WX (24 cores), 125 GB RAM, and two NVIDIA RTX 6000 Ada GPUs. The
torch-based attacks (MultiHeadMLP, ARFFormer, CondDDPM, CondRePaint) use a GPU
when one is present and fall back to CPU otherwise, so a GPU changes how long
they take, not what they compute.

### Software Requirements

- **Docker** 24.0 or newer, on Linux, macOS (including Apple Silicon) or
  Windows. The images supply everything else.
- **Python** 3.9 for the attacks and analysis, with packages pinned in
  `docker/requirements-attacks.txt`. A second environment (Python 3.10,
  `docker/requirements-sdg.txt`) holds the generators whose dependencies conflict
  with the attack stack; only the full image includes it.
- **R** with `synthpop` and `sdcMicro`, for the Synthpop, RankSwap and
  CellSuppression generators only. The full image includes R 4.5.
- **Gurobi**, for the LinearReconstruction attack only. It needs a licence (free
  for academics) and is not installed in the images; see *Limitations*.
- **Models**: none to download. The one pre-trained model, TabPFN's checkpoint,
  is fetched when the image is built.
- **Datasets**: none are redistributed. `experiment_scripts/fetch_dataset.py`
  downloads Adult and CDC Diabetes, the two that Experiments 3 and 4 use.
  California Housing ships with scikit-learn, NIST Arizona needs a free IPUMS
  registration, and NIST SBO is available from NIST on request. `data/dummy/`
  is a small bundled dataset in the same layout, so the whole pipeline runs
  with no downloads.

### Set Up the Environment

On Linux or macOS:

```bash
git clone --recurse-submodules https://github.com/steveng9/Reconstruction.git
cd Reconstruction
docker build -f docker/Dockerfile --build-arg UID=$(id -u) --build-arg GID=$(id -g) -t recon-artifact:latest .
docker run --rm -it -v "${PWD}":/workspace -w /workspace recon-artifact:latest bash
```

The two `--build-arg` flags make the user inside the container match yours, so
that files the experiments write into the mounted repository belong to you.

On Windows, use a WSL2 shell and the commands above. In PowerShell, drop the two
`--build-arg` flags.

On an Apple Silicon Mac no extra flag is needed. Both images are built for
`linux/amd64` (two pinned dependencies have no arm64 build), so Docker Desktop
runs them under emulation: correct, but slower.

If you cloned without `--recurse-submodules`, run
`git submodule update --init --recursive`.

Everything below runs inside the container, from the repository root. No paths
need editing. `python paths.py` prints where the code looks for data, and four
environment variables override the defaults:

| Variable | Default | Holds |
|---|---|---|
| `RECON_DATA_ROOT` | `<repo>/data` | datasets and generated synthetic data |
| `RECON_EXTERNAL_ROOT` | `<repo>/external` | the two submodules |
| `RECON_RESULTS_DB` | `<repo>/experiment_scripts/results.db` | scored results |
| `RECON_TABLE_OUT` | `<repo>/expected_output/tables` | rebuilt tables and figures |

**The full image.** The light image runs every attack and seven generators: the
six DP ones (MST, AIM, PrivBayes, PrivSyn, MWEM-PGM, PrivateGSD) and TabDDPM.
That is all this document uses. To generate data with TVAE, CTGAN, ARF,
Synthpop, RankSwap or CellSuppression, build the full image instead:

```bash
docker build -f docker/Dockerfile.full --build-arg UID=$(id -u) --build-arg GID=$(id -g) -t recon-artifact:full .
```

It is about 23 GB and takes much longer to build. Use it exactly like the light
one. It holds two conda environments, `recon_` for the attacks and `sdg` for the
extra generators, and `sdg/generate_synth.py` sends each job to the environment
that can run it. Its R packages are newer than the ones the paper's data was
generated with, so data regenerated there is not bit-identical to ours.

To see which attacks and generators run in your environment, rather than which
merely import:

```bash
python experiment_scripts/verify_registries.py
```

This runs every attack on the bundled dataset and asks every generator for a
small synthetic table. It takes about 25 minutes in the light image and prints
one `ok` or `FAIL` line per attack and generator among the training logs. There,
25 of the 28 attacks and 7 of the 12 generators run. The rest name the
dependency they are missing: Gurobi for the three LinearReconstruction variants,
and the full image for the other five generators.

## Artifact Evaluation

### Main Results and Claims

#### Main Result 1: The generator governs risk far more than the attack does

Across the attack × generator grid on Adult (`tab:ra_mean_adult`), mean
$R_{adv}$ varies much more between generators than between attacks on any one
generator. Supported by Experiment 1 and, at reduced scale, Experiment 3.

#### Main Result 2: De-identification methods are the most exposed

Cell Suppression, RankSwap and Synthpop sit at the high-risk end of the same
table, well above the DP generators. Supported by Experiment 1.

#### Main Result 3: CoBP-RA is the strongest attack measured

CoBP-RA, introduced in the paper, has the highest mean $R_{adv}$ of the attacks
evaluated (`tab:ra_mean_adult`). Supported by Experiment 1 and, at reduced
scale, Experiments 2 and 3.

#### Main Result 4: DP lowers reconstruction up to ε ≈ 10, and risk flattens above it

Across six DP mechanisms and ε from 0.1 to 1000, $R_{adv}$ falls steadily as ε
drops below about 10 and is close to flat above it (`fig:eps_curves`, with
paired tests in `tab:eps_stats`). Supported by Experiment 1 and, at reduced
scale, Experiment 4.

#### Main Result 5: Most reconstruction is distributional, not memorization

Attacks score almost as well on held-out records as on training records for
most generators, so their success mostly reflects population structure; where
the gap is large, it concentrates on atypical records
(`tab:memorization_and_ds_risk`, `tab:disparate_impact`). Supported by
Experiment 1.

### Experiments

#### Experiment 1: Rebuild the paper's tables and figures

- Time: 2 human-minutes + ~1 compute-minute
- Storage: <10 MB

```bash
python reproduce.py
```

This recomputes each table and figure from `results.db` and seven result CSVs in
`experiment_scripts/`, writes them to `expected_output/tables/`, and ends with
`done: 22 files written`. It supports Main Results 1 to 5 at full scale.

| Output | Paper object |
|---|---|
| `table1_ra_mean_adult.tex` | `tab:ra_mean_adult` (Results 1 to 3) |
| `table2_quality_overview.tex` | `tab:quality_overview` |
| `fig_eps_curves.pdf` and four more `fig_eps_curves_*.pdf` | `fig:eps_curves` and the four appendix ε figures (Result 4) |
| `STATS_eps_curve.md` | `tab:eps_stats` (Result 4) |
| `table7_memorization.tex`, `STATS_memorization.md` | `tab:memorization_and_ds_risk`, `tab:memo_stats` (Result 5) |
| `table9_disparate_impact.tex` | `tab:disparate_impact` (Result 5) |
| `table6_mia_comparison.tex` | `tab:mia_comparison` |
| `table_ra_mean_cdc.tex`, `table_cdc_100k.tex`, `table_ra_mean_nist_sbo.tex` | `tab:ra_mean_cdc`, `tab:cdc_100k`, `tab:ra_mean_nist_sbo` |
| `table4_eps_sweep_compact.tex`, `table4_eps_sweep_full.tex` | the values plotted in the appendix ε figures, as tables |

Objects are named by their LaTeX `\label`, which you can match to the PDF by
caption. `python reproduce.py --list` prints this mapping.

The rebuilt tables carry the same values as the published ones, cell for cell.
(The one exception is two AUCs in the Adult block of `tab:mia_comparison`, which
come out 0.01 away from the printed value.) Each `.tex` file holds the body of
the table, one row per line, so it can be read next to the PDF.

To check your output against the reference copies without overwriting them:

```bash
python reproduce.py --out /tmp/check
diff -r expected_output/tables /tmp/check
```

The `.tex` and `.md` files should be identical. The PDF and PNG files will
differ in their embedded timestamps and font rendering.

#### Experiment 2: One attack on the bundled dataset

- Time: 2 human-minutes + ~1 compute-minute

```bash
python master_experiment_script.py --n_runs 1
```

This runs `configs/demo_dummy.yaml`: CoBP-RA against an MST (ε=10) release of
the bundled dataset, with no downloads. Near the end of the output, the line
starting `ave:` gives the mean $R_{adv}$. Expect about **40**, against **33.88**
for the `Mode` baseline. Change `attack_method` in the config to try another
attack (`Mode`, `RandomForest`, `KNN`, `NaiveBayes`, `MultiHeadMLP`, …;
`attacks/__init__.py` lists them all), or pass `--config <path>` to run a
different config. `README.md` walks through the same run on the Adult dataset.

#### Experiment 3: Reduced attack × generator grid

- Time: 10 human-minutes + ~40 compute-minutes
- Storage: ~100 MB

This reruns a corner of `tab:ra_mean_adult` from raw data, to show that the
numbers in `results.db` come out of this code.

```bash
python experiment_scripts/fetch_dataset.py adult
bash experiment_scripts/run_artifact_experiment3.sh
```

The first command downloads Adult and carves disjoint training samples. The
second generates synthetic data with four generator settings (MST at ε = 1, 10
and 100, and AIM at ε = 1) and attacks each with Mode, KNN, Random Forest, Naive
Bayes and CoBP-RA, on two training samples. All of it runs on CPU in the light
image. It took 14 minutes on our 24-core workstation, most of that generating
the synthetic data; the 40 minutes above allow for a laptop. `WORKERS=<n>` sets
the number of attack processes (4 by default).

The script ends by printing the mean $R_{adv}$ per attack:

| Attack | This experiment | Same four columns of `tab:ra_mean_adult` |
|---|---|---|
| CoBP-RA | 24.6 | 24.5 |
| Random Forest | 23.5 | 23.1 |
| Naive Bayes | 21.0 | 20.8 |
| KNN | 20.6 | 19.7 |
| Mode (baseline) | 10.4 | 10.3 |

Expect each attack within about a point of the paper and the same ordering,
with CoBP-RA first (Main Result 3) and every attack far above the baseline. The
small gap is expected: the paper averages five training samples, and this
averages two.

#### Experiment 4: Reduced ε sweep

- Time: 10 human-minutes + ~50 compute-minutes
- Storage: ~200 MB

This reruns the ε sweep of Main Result 4 on CDC Diabetes with three of the six
mechanisms (MST, PrivBayes, PrivSyn), over the paper's nine budgets (0.1 to 1000).

```bash
python experiment_scripts/fetch_dataset.py cdc_diabetes
bash experiment_scripts/run_cdc_dp_sweep_pipeline.sh
```

The script ends by printing the mean $R_{adv}$ at each budget. Our run gave:

```
epsilon        0.1    0.3      1      3     10     30    100    300   1000
MST           42.2   42.8   42.9   44.0   44.7   44.8   45.0   44.9   45.0
PrivBayes     42.8   42.0   43.3   43.5   44.8   43.3   44.7   45.3   44.8
PrivSyn       42.3   43.3   43.6   44.6   45.7   45.3   45.3   45.6   45.4
```

Expect the same shape as in `fig_eps_curves.pdf`: $R_{adv}$ climbs by two to
three points between ε = 0.1 and ε = 10 and moves little after that. Individual
values shift by a few tenths between runs.

The run took 14 minutes on our 24-core workstation with the default 12 worker
processes. With 4 cores, set `SWEEP_WORKERS=4` and allow about two and a half
hours. Results go to `experiment_scripts/results_reproduction.db`, so the
shipped `results.db` is never modified.

## Limitations

1. **The full sweep is not rerun here.** Producing all 50,826 runs from raw data
   takes CPU-weeks, so the scored results ship in `results.db`, Experiment 1
   rebuilds the tables from them, and Experiments 3 and 4 rerun small slices
   from raw data.

2. **Some supporting tables do not rebuild yet.** Experiment 1 covers every
   table and figure behind the five main results. Thirteen supporting objects
   (per-dataset quality profiles, the QI-sensitivity tables, the per-feature and
   per-attack breakdowns, the ensembling heatmap and the quality star chart) have
   no generator yet, although the data behind all but the heatmap is in the
   repository. `python reproduce.py --list` names each one, and
   `TABLE-COVERAGE.md` tracks them.

3. **Two datasets cannot be redistributed.** Results on NIST Arizona and NIST
   SBO can be rebuilt from `results.db`, but rerunning those attacks requires
   obtaining the data (IPUMS registration; NIST on request).

4. **LinearReconstruction needs Gurobi.** The solver is commercial and its
   licence cannot be shipped in an image, so the three LinearReconstruction
   variants report that they are unavailable. With an academic licence
   (<https://www.gurobi.com/academia/>), mount it and install the bindings:

   ```bash
   docker run --rm -it -v "${PWD}":/workspace -w /workspace -v "$HOME/gurobi.lic":/opt/gurobi/gurobi.lic:ro -e GRB_LICENSE_FILE=/opt/gurobi/gurobi.lic recon-artifact:latest bash
   pip install --user gurobipy==11.0.3
   ```

5. **Runs are not bit-reproducible.** Several attacks (random forests, MLPs, the
   diffusion samplers) are stochastic, and individual scores move by a few
   tenths of a point between runs. Rebuilding tables from `results.db` is
   deterministic.

## Notes on Reusability

The framework is built to be extended, and `README.md` covers each of these in
more detail.

**Add an attack.** Write
`my_attack(cfg, synth, targets, qi, hidden_features) -> (reconstructed_df, probas, classes)`,
register it in `ATTACK_REGISTRY` in `attacks/__init__.py`, and add its defaults
to `attack_defaults.py`. Every sweep script and both wrappers (chaining,
ensembling) can then use it. `examples/add_your_own_attack.py` does all three
steps in one runnable file and scores the new attack against the baseline and
CoBP-RA on the bundled dataset in about 30 seconds.

**Add a generator.** Write `generate(train_df, meta, **config) -> synthetic_df`
and register it in `SDG_REGISTRY` in `sdg/__init__.py`.

**Add a dataset.** Create `<dataset>/full_data.csv` and `meta.json` under the
data root, add QI definitions to `get_data.py`, and run `sdg/generate_synth.py`
with `SDG_DATASET=<dataset>` to cut training samples and generate synthetic
data. `data/dummy/` is a small dataset in this layout.

**Use the results without the code.** `results.db` is plain SQLite: one row per
scored run, with per-feature scores in a companion table. `DATABASE.md`
documents the schema, the label conventions, and worked queries, and
`python examples/query_results_db.py` runs them with the standard library only.

**Beyond reconstruction.** The same harness runs membership inference
(`--mode mia`), and `experiment_scripts/compare_mia_ra.py` implements the
paper's reduction that puts reconstruction and membership inference on one
scale.
